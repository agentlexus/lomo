========================================================
N24  R1=1.000           // пользовательский коэффициент масштаба (в начале Path, до операции)
N45  ASCALE X=R1 Y=R1   // актив. масштаб X/Y (после M8, ПЕРЕД первым подъездом G0)
N50  M52                // разблокировать ось C перед Engage
N51  G2 X18 Y0 Z-29.5 I-34.5966 J-14.92 TURN=0 F597   // подход дугой (без G41/G42)
N53  G1 G91 C-360.1 F200                              // Cutting: вращение стола C на -360.1 deg инкремент.
N55  G90                                               // возврат абс. перед Retract (отдельная строка)
N56  G2 X14.92 Y-14.92 Z-29.2408 I-37.6766 J0 TURN=0 F600 // Retract дугой (G90 уже активен)

СМЫСЛ:
- обработка боковой/торцевой поверхности бобышки = при неподвижной фрезе на радиусе X=R поворот стола C.
- компенсация радиуса — НЕ через G41/G42, а через ASCALE (масштаб пути X1..): фреза отводится/прижимается наклоном R1.
- угол C-360.1 (не ровно 360) — небольшой нахлёст для чистого стыка.

8. ФИНАЛЬНЫЕ УТОЧНЕНИЯ (закрытые вопросы)
========================================================
1) "Вывод данных контакта трассировки" — это ТОЛЬКО визуальное представление траектории в NX,
   на данные для поста НЕ влияет. G41 появляется из-за включённого там же КОРРЕКТОРА
   инструмента (Cutter Compensation) — источник mom_cutcom_status / G41/G42.
   ЗАДАЧА lock-режима: подавить вывод корректора (G41/G42/G40) в пост;
   координаты пути остаются центральными (что даёт 14.92/18 как в эталоне).

2) R1 — создать отдельное поле ввода в UDE (тип выбора/число). Доступ в пост по аналогии
   с передачей переменных из операций NC UDE (mom_ude_<имя>, тип REAL, default 1.0).
   Конкретное имя mom_ude_-переменной создаётся вместе с добавлением поля в UDE.
   (поле надо доделать/создать в настройке UDE, затем пост читает его значение)

3) Лишний позиционирующий кадр X<R>/C0 перед C-поворотом НЕ выводить.
   фреза уже на радиусе к началу Cutting (от Engaging-дуги). Единственный режущий кадр:
        ;Cutting
        G1 G91 C-360.1 F200
        G90
